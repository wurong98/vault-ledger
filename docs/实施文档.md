# LedgerBox（账匣）第一版实施文档

> 版本：0.3.0 · 日期：2026-11-14  
> 状态：P0–P7 已实现并通过自动化测试；P8 的真机验证尚未进行。  
> 依据：[技术设计](./技术设计.md)  
> 约束：Ubuntu 24+、Node.js ≥ 22.12、TypeScript、单用户、手机优先。

## 1. 实施目标与顺序

本轮只编写文档。后续开发从空仓库起步，不沿用已删除的 Python 原型，不把旧原型描述成已实现功能。

第一版按垂直流程逐段交付：

```text
项目骨架 → 加密存储 → 首次引导/解锁 → 账本与手动记录
→ 截图/DeepSeek 候选 → 借还款与修改 → 自然语言查询
→ 手机备份/恢复 → 完整验收与部署说明
```

每个阶段都应提供可运行结果和验证记录；先实现可手动录入的确定性路径，再接模型，避免模型不可用时无法调试账本。

### P0：骨架与共同契约

任务：

- 建立 React/Vite 前端、Fastify 后端、共享 TypeScript/Zod 契约。
- 开发模式代理 API；生产由同一服务提供构建后的前端。
- 配置按“环境变量 > 加密设置 > 默认值”解析，区分公共配置与秘密。
- 统一错误 `{code, message, requestId}`；校验错误不能回显敏感输入。
- 添加数据目录、`.env`、备份文件和临时文件的 Git 忽略规则。

完成条件：空环境能启动并显示“创建账本 / 从备份恢复”；前端包不包含服务端秘密；类型检查和构建通过。

### P1：加密存储与原子提交

任务：

- 实现 scrypt 异步派生、随机 DEK、AES-GCM 包装与文件加密。
- 固定 v1 算法注册表、AAD 编码、字节顺序和序列化规则，并写入格式测试。
- 实现 VaultRepository、BlobStore、单写队列与进程级数据目录锁。
- 初始化创建完整存储代，写入 `CURRENT` 前不得暴露半初始化状态。
- 实现附件先行、manifest 后行的原子保存和崩溃恢复。
- 上传流不使用会把明文图片落入 `/tmp` 的默认磁盘缓冲。

建议接口：

```ts
interface VaultRepository {
  initialize(password: string): Promise<void>;
  unlock(password: string): Promise<void>;
  lock(): Promise<void>;
  readManifest(): Readonly<Manifest>;
  commit(expectedRevision: string, change: DomainCommand): Promise<CommitResult>;
  snapshot(): Promise<EncryptedSnapshotHandle>;
}
```

所有持久修改必须经领域命令和写队列，不能让路由直接修改共享对象。修改失败不得把未提交的数据留在内存里当作已保存。

完成条件：正确密码恢复内容；错误密码和密文篡改拒绝；同一数据两次加密 nonce 不同；掉电/写失败模拟后只能看到完整旧版或新版；磁盘上搜索不到虚构测试姓名、金额和截图明文。

### P2：首次引导、解锁与模型设置

任务：

- 首次新建表单：密码、确认密码、密码不可找回提示。
- DeepSeek 设置表单：Key、模型、连接测试、配置来源和错误提示。
- Key 加密保存；接口只回传 `configured`、`source` 和必要掩码，永不返回完整 Key。
- 若存在环境变量 Key，则说明优先级；更改本地设置不会遮蔽环境变量的实际值。
- 创建首个账本，允许后续新增；未配置模型时提供手动记录功能和补全配置入口。
- 实现引导中断续接、会话 Cookie、超时、全部设备锁定、限流和 CSRF。

完成条件：不编辑配置文件也能完成首次使用；刷新和重启后需解锁；Key 测试只发送固定非财务消息；错误 Key 可修正，不影响已保存数据。

### P3：账本、联系人与手动结构化记录

任务：

- 实现创建/选择账本、账户、联系人；所有 ID 做账本归属校验。
- 实现记录列表、筛选、详情、手动创建及金额转换。
- 明确每次请求携带 ledgerId；服务端不依赖浏览器“当前账本”全局变量。
- 实现完整交易类型、双分录及当前有效版本统计。
- 添加借还款按联系人汇总，日常收支不包含借款、还款和内部转账。

完成条件：借出 500、收回 200，显示应收 300；借入 800、归还 300，显示应付 500；日常收入/支出不因此增加；账本切换无串数据。

### P4：完整截图与 DeepSeek 提取

任务：

- 上传 JPEG/PNG/WebP，检查真实格式、大小、像素，不信任扩展名和 MIME 声明。
- 原图加密保存；显示完整预览、缩放、长图滚动、选择其他来源。
- 保存来源说明、内容 hash 和来源到记录的一对多关系。
- 相同图片提示复用来源，同一个 source 可新增不同记录，不把图片去重等同于交易去重。
- DeepSeek 适配器：图文请求、JSON 模式、超时、并发、输出长度、错误归一化。
- 提取结果存为候选，与正式记录分离；字段可修改，未知日期/账户/联系人须确认。
- 候选绑定 sourceId、ledgerId、模型和提示词版本；切换账本或锁定时不能把迟到响应展示给另一个上下文。
- 识别失败保留加密来源，允许重试或手动录入；不自动重复计费重试。

完成条件：手机选图加说明 → 识别 → 修改 → 确认 → 详情看原图。确认请求断网重试不重复入账。多笔截图提示人工选择，不自动合计。

### P5：修订、作废与借还款展示

任务：

- 编辑提交 expectedRevision，冲突返回 `409 REVISION_CONFLICT`，不能覆盖新版本。
- 一次提交内完成冲销旧分录、新分录、修订记录与审计。
- 作废保留原图和历史；所有有效统计排除作废记录。
- 提供“对方欠我 / 我欠对方”详情及全部相关记录，支付方式和备注可筛选。
- 同名联系人必须选择，不自动按姓名合并。

完成条件：修改 500 为 600 后历史仍有 500，当前统计只算 600；再作废则当前统计不含此笔；原始识别内容不被覆盖。

### P6：自然语言查询

任务：

- 定义 QueryIntent Schema 与允许操作，不执行模型生成的代码或 SQL。
- 提供日期上下文及最小必要词典，允许模型返回“不支持/需澄清”。
- 本地解析引用 ID，强制 ledgerId 边界，应用筛选并执行精确统计。
- 展示实际条件、匹配笔数、分项金额和可打开来源的记录。
- 借还款当前余额使用全部有效历史；期间范围只展示期间变动。

完成条件：“张三还欠我多少”返回可复算的本金与对应借还款；“本月餐饮花费”与直接筛选一致；恶意问题不能修改、跨账本或读取服务器文件。

### P7：手机完整备份和恢复

任务：

- 设置和首页提供“下载加密备份”；生成包含全部账本的完整快照。
- 归档时固定一个已提交版本，流式读取不可变密文附件；不先打出含明文的 ZIP。
- 返回附件文件名、正确响应类型和 `no-store`。
- 仅记录“最近发起下载”，显示版本和未包含的新修改，不误称手机已成功保存。
- 首次页面和设置页提供恢复；验证完整归档后显示预览，再要求确认替换。
- 恢复使用新存储代，原子切换 `CURRENT`，保留旧代、撤销旧会话。
- 处理失败、取消、重启的临时密文清理，不允许部分恢复。

完成条件：在数据目录 A 创建多账本、截图、借还款及修改历史 → 下载 → 用全新目录 B 上传恢复 → 原图字节、记录、审计和统计均一致。错密码、缺附件、旧/未知版本、损坏标签及 ZIP 路径攻击均拒绝，原数据不变。

### P8：移动端与交付

任务：

- 手机布局、触摸目标、键盘类型、加载状态、错误恢复、长图与下载入口。
- iPhone Safari 与 Android Chrome 真机分别验证，不以桌面缩小窗口代替全部真机测试。
- 离线显示明确状态，不缓存敏感内容到持久化浏览器存储。
- README 说明首次引导、Ubuntu 启动、HTTPS/手机访问、备份下载位置和换机恢复。
- 提供 `.env.example`、生产构建和单进程启动说明。

完成条件：所有第一版验收项通过，真实模型及真机测试状态有据可查；没有 Key 或设备时明确标“未验证”，不伪造通过。

## 4. 接口草案

统一前缀 `/api/v1`。除初始化、解锁和必要的初始化状态外，接口必须有有效会话。变更接口有同源/CSRF 验证和幂等键；不可把 Key、密码放在 URL 中。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/status` | 初始化/锁定状态、公开配置是否完整，不含业务数据或 Key |
| POST | `/setup` | 仅未初始化时创建加密数据空间和会话 |
| POST | `/unlock` | 验证密码并创建浏览器会话 |
| POST | `/lock` | 注销当前会话；全部设备锁定单独显式选项 |
| GET/PATCH | `/settings/llm` | 查看脱敏配置/修改加密配置 |
| POST | `/settings/llm/test` | 服务端用固定消息测试连接 |
| GET/POST | `/ledgers` | 列出/创建账本 |
| GET/POST | `/ledgers/:id/accounts` | 账本内账户 |
| GET/POST | `/ledgers/:id/contacts` | 账本内联系人 |
| GET/POST | `/ledgers/:id/sources` | 来源列表/上传原图和说明 |
| GET | `/sources/:id/image` | 解密后按权限返回完整原图 |
| POST | `/sources/:id/extractions` | 创建识别任务，返回任务 ID |
| GET | `/extractions/:id` | 查询状态、候选、证据和不确定字段 |
| POST | `/extractions/:id/confirm` | 用户确认候选为正式记录 |
| GET/POST | `/ledgers/:id/records` | 流水筛选/手动创建，可指定已有 sourceId |
| GET/PATCH | `/records/:id` | 详情/带 revision 的修订 |
| POST | `/records/:id/void` | 作废并冲销 |
| GET | `/records/:id/history` | 修订与审计 |
| GET | `/ledgers/:id/debts` | 本地确定性借还款统计 |
| POST | `/ledgers/:id/query` | 自然语言查询意图及本地结果 |
| POST | `/backups` | 创建固定版本的快照任务，返回短期任务 ID |
| GET | `/backups/:id/download` | 会话鉴权后下载对应完整密文归档 |
| POST | `/restores/preview` | 接收备份和密码，验证并暂存恢复计划 |
| POST | `/restores/:id/confirm` | 当前 revision 未变化时执行恢复 |
| DELETE | `/restores/:id` | 取消，清理暂存密文 |

恢复例外：没有数据空间时可在引导中调用 preview/confirm，使用短期 HttpOnly 引导会话和同源校验；已有数据时必须先解锁。恢复计划绑定创建它的会话、当前数据版本和短期有效期，避免预览后误覆盖新修改。

### 4.1 请求示例

创建密码通过 HTTPS 请求体发送，不写日志：

```json
{
  "password": "用户输入的长口令",
  "passwordConfirmation": "用户输入的长口令"
}
```

候选确认的额外上下文（业务字段按共享 Schema 传递）：

```json
{
  "ledgerId": "led_example",
  "sourceId": "src_example",
  "expectedCandidateRevision": "1",
  "record": {
    "type": "lend",
    "amount": "500.00",
    "currency": "CNY",
    "occurredOn": "2026-11-14",
    "accountId": "acc_example",
    "contactId": "contact_example",
    "paymentMethod": "微信",
    "remark": "月底还"
  }
}
```

每个创建/确认请求使用随机 `Idempotency-Key`；作用域为数据空间、账本与操作，同键同内容返回原结果，同键不同内容返回冲突。键与请求摘要、结果 ID 必须随正式记录持久化，重启后仍有效，不能只放内存。

### 4.2 查询意图示例

```json
{
  "operation": "debt_balance",
  "filters": {
    "contactId": "contact_example",
    "dateFrom": null,
    "dateTo": null,
    "type": null,
    "categoryId": null,
    "accountId": null,
    "paymentMethod": null,
    "keyword": null
  },
  "supported": true,
  "clarification": null
}
```

服务端绑定账本，Schema 不允许模型提供任意 ledgerId。金额响应全部为字符串；应收和应付分别返回，不净额抵消不同方向债务。

### 4.3 错误码

- `LOCKED`：会话失效，需要重新解锁。
- `SETUP_REQUIRED` / `LLM_CONFIG_REQUIRED`：进入引导或配置页。
- `INVALID_PASSWORD_OR_BACKUP`：不泄漏密码与密文细节。
- `MODEL_UNAVAILABLE` / `MODEL_RESPONSE_INVALID`：保留来源，可重试/手动录入。
- `VALIDATION_FAILED`：展示安全的字段提示，不回显原始请求。
- `REVISION_CONFLICT` / `IDEMPOTENCY_CONFLICT`：重新加载或纠正请求。
- `UNSUPPORTED_BACKUP_VERSION` / `BACKUP_INTEGRITY_FAILED`：不改动原数据。
- `LIMIT_EXCEEDED` / `RATE_LIMITED`：给出具体可操作的上限/等待提示。
- `STORAGE_LOCKED`：数据目录被另一个进程占用。
- `BACKUP_TOO_LARGE`：归档或恢复超过体积上限。
- `EXTRACTION_TIMEOUT`：模型请求超时，来源已保留可重试。
- `NOT_FOUND` / `FORBIDDEN`：资源不存在或不属于当前账本/会话。
- `RATE_LIMITED`：密码尝试进入冷却，响应带 `retryAfterSeconds`。

## 5. 环境配置契约

| 变量 | 默认/建议 | 行为 |
|---|---|---|
| `HOST` | `127.0.0.1` | 首次初始化默认不暴露公网 |
| `PORT` | `8000` | Node 同源服务端口 |
| `DATA_DIR` | `~/.local/share/ledgerbox` | 不在 Git 仓库内 |
| `APP_ORIGIN` | 本机开发地址 | 生产明确配置 HTTPS 源，供同源检查 |
| `TRUST_PROXY` | `false` | 仅在明确受信代理环境开启 |
| `SESSION_IDLE_MINUTES` | `30` | 空闲会话上限 |
| `DEEPSEEK_API_KEY` | 无 | 可选环境注入，优先于页面保存值 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | 非默认目的地须管理员配置，不接受账单内容指定 |
| `DEEPSEEK_MODEL` | `deepseek-flash` | 实施时验证当前账户图文能力 |
| `LLM_TIMEOUT_MS` | `120000` | 上游超时 |
| `LLM_MAX_CONCURRENCY` | `2` | 有界队列，满时拒绝而非无限排队 |
| `MAX_IMAGE_BYTES` | `8388608` | 单图 8 MiB |
| `MAX_IMAGE_PIXELS` | `24000000` | 解码像素上限，另限制边长 8192 |
| `MAX_BACKUP_BYTES` | `536870912` | 归档/恢复默认 512 MiB，上限需可配置并在下载前提示 |

环境变量中的秘密不写回加密配置；环境值不随备份迁移。Web 端只能编辑允许的模型设置，不能通过页面修改任意服务器路径或开启任意出站地址。

密码不支持默认自动解锁。需要无人值守能力时单独设计，不能为了省事把密码放进前端或公共配置。

## 6. 状态与并发

### 6.1 状态机

```text
应用：uninitialized → password_created → llm_config_pending → ready
解锁：locked → unlocked → expired/locked
来源：uploaded → extracting → review_required/failed → linked
候选：draft → validated → confirmed / rejected
记录：active → revised → active；active → voided
备份：requested → snapshot_fixed → downloading → served/failed
恢复：uploaded → validated → previewed → confirmed → switched / cancelled/failed
```

`served` 只代表服务器已完成响应，不能代表手机下载已保存；没有模型配置时应用可手动使用。来源状态不限制它关联多笔记录。

### 6.2 并发与一致性要求

- 所有持久更改进入同一个写入队列，成功后再更新内存中的当前版本。
- 同一数据目录禁止多进程写入；不启用多 worker 或集群模式。
- 每次提交递增数据修订版本，记录修订版本独立递增。
- 图片不可变，修改备注不重写原图。
- LLM 网络请求在写队列之外执行，返回时重新验证会话和账本上下文。
- 锁定或会话失效后，不将迟到模型结果发送给客户端；任务结果处理须与加密存储状态一致。
- 备份保留固定版本的附件引用，下载期间不得垃圾回收。
- 恢复确认要求当前修订版本仍等于预览时版本，否则重新预览。

## 7. 测试与验收矩阵

| 领域 | 必测场景 | 判定 |
|---|---|---|
| 首次引导 | 无配置、环境 Key、错误 Key、中断再进、已有备份恢复 | 不需改配置文件即可使用；不覆盖已初始化数据 |
| 密码与会话 | 错密码、连续失败、刷新、超时、重启、锁定全部设备 | 不泄漏数据；需要时重新解锁 |
| 冷却阶梯 | 前 3 次失败免冷却；第 4 次起 1 分钟→1 小时→1 天→1 周→1 月→1 年；冷却期内正确密码也被拒；重启重置 | 阶梯与文档一致，不提前跳级 |
| 加密 | 错 Key/标签、交换密文、nonce 新鲜性、目录权限 | 篡改拒绝；明文不落盘 |
| 金额 | 0.10+0.20、超精度、负数、过大值、序列化 | 0.30；非法输入拒绝；无浮点误差 |
| 借还款 | 借出/收回、借入/归还、部分归还、同名人、超额归还 | 分方向、分人、分账本正确；不混入日常收支 |
| 多账本 | 切换、伪造其他账本 ID、识别期间切换 | 查询、来源、记录不串账本 |
| 图文录入 | 长图、无日期、非人民币、伪装格式、多笔截图 | 可看完整图；不猜日期、不自动换汇或合计入账 |
| 幂等 | 重复点击、响应丢失后重试、重启后重试 | 同一请求仅一条正式记录 |
| 修订 | 并发编辑、修改金额、作废、查询历史 | 旧版本存在，当前统计正确，分录平衡 |
| AI 查询 | 日期/人/方式筛选、当前欠款、期间变动、提示注入 | 结果可复算；无写权限和跨账本能力 |
| 下载 | 所有账本、原图、同时录入、中断、超上限 | 完整一致快照；不谎称手机已保存 |
| 恢复 | 空目录、已有数据、错密码、缺文件、损坏、未知版本 | 验证失败不改变原数据；成功后重新解锁 |
| 归档安全 | 路径穿越、重复条目、符号链接、解压炸弹 | 有界处理，无越界文件写入 |
| 故障恢复 | 元数据写入/恢复切换前后断电、磁盘满 | 加载完整旧版或新版，无半恢复 |
| 手机 | Android/iPhone 选图、键盘、缩放、下载、选择备份恢复 | 真机完成主流程 |

自动测试使用虚构数据和模拟 DeepSeek 服务，不默认产生调用费用。真实 DeepSeek 冒烟测试需测试人员主动启用、提供环境 Key，并仅发送虚构截图与说明。

## 8. 第一版最终验收脚本

1. 用全新数据目录启动；手机/浏览器进入首次引导。
2. 设置密码，填写 DeepSeek Key，测试连接，创建“个人”账本。
3. 上传虚构借款截图，说明“微信借给张三 500”，确认日期、对方、账户、方式后保存。
4. 再记“张三归还 200”，查看应收为 300，日常收支不计这两笔。
5. 问“张三还欠我多少”，结果为 300，并展示两条来源记录。
6. 将原借出修订为 600，应收为 400，历史仍能看到原来的 500。
7. 创建第二个账本并切换，验证两个账本记录与查询互不影响。
8. 详情打开完整长截图并缩放核对。
9. 下载一份带时间和版本的加密备份，到手机文件管理器确认文件存在。
10. 在另一个空数据目录启动，上传该备份、输入密码、确认恢复。
11. 检查两个账本、原图、联系人、借还款、修订与模型配置完整恢复；应收仍为 400。
12. 修改一个备份字节再尝试恢复，必须拒绝且不影响已恢复的数据。

上述 12 步已由 `tests/e2e/acceptance.test.ts` 以自动化方式跑通（模型部分使用模拟上游，图片使用程序生成的虚构截图）。真实 DeepSeek 调用与 Android/iPhone 真机操作仍未验证，不能据此把 P4/P6/P8 标记为“已验证”。
